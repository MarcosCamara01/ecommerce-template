# Security Policy

## Supported versions

Security fixes are applied to the latest code on `master` and, when releases exist, to the latest supported release. Older commits, forks, and unmaintained deployments are not supported.

## Reporting a vulnerability

Do not open a public issue, discussion, or pull request for a suspected vulnerability.

Use GitHub's **Report a vulnerability** button on the repository Security page:

https://github.com/MarcosCamara01/ecommerce-template/security/advisories/new

Include:

- the affected revision and component;
- reproducible steps or a minimal proof of concept;
- the security impact and realistic attack prerequisites;
- suggested mitigations, if known;
- whether the issue or proof of concept has been shared elsewhere.

Do not access data that does not belong to you, disrupt a hosted service, retain sensitive data, or publish the vulnerability before a fix and disclosure plan have been coordinated.

The maintainer will acknowledge reports as availability permits, validate the impact, coordinate a remediation, and credit reporters who want attribution. This project does not currently promise a fixed response-time SLA or a bug bounty.
